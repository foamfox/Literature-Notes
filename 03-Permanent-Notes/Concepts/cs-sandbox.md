# 沙箱 (Sandbox)

> **类型**：概念卡片  
> **领域**：计算机安全、操作系统、网络安全、虚拟化技术  
> **来源**：综合整理（知乎技术专栏、华为信息百科、Wikipedia、NIST、Chromium开源项目等）

---

## 1. 定义

### 一句话定义

> **沙箱是一种通过「隔离 + 权限限制 + 资源虚拟化」为不可信程序构建受控执行环境的安全机制，使其在划定边界内运行而不影响外部真实系统。**

### 详细解释

沙箱（Sandbox）源于儿童沙盒游戏的隐喻——在一个与外界隔绝的小世界里自由实验，而不会造成真实破坏。在计算机安全领域，沙箱通过以下三种核心手段实现 containment（ containment 与隔离）：

1. **资源隔离**：为被隔离程序划定独立的虚拟地址空间、文件系统视图、网络栈和进程命名空间，使其"看到的世界"是虚拟的、受限的。
2. **权限控制**：通过系统调用拦截（如 Seccomp-BPF）、强制访问控制（如 SELinux/AppArmor）或 Hook 技术，剥夺或严格限制程序对宿主系统资源（真实文件、硬件、网络、其他进程）的访问能力。
3. **虚拟化 / 重定向**：对程序的资源请求进行中间人转发或重定向。例如，写操作被重定向到沙箱自身的临时区域，调用真实支付接口被替换为返回模拟结果，程序以为自己在生产环境运行，实则全程在"演戏"。

沙箱技术最早可追溯至 **软件故障隔离（Software-based Fault Isolation, SFI）**，其初衷是通过软件手段隔离不可信模块以防止故障扩散，而非针对恶意软件。20 世纪 90 年代后，随着分布式计算和网络安全威胁的演进，沙箱逐渐演变为以安全隔离和动态行为分析为核心的主动防御技术。

### 类比

向研一学生解释：沙箱就像**生物实验室的负压隔离舱**——研究员可以在里面操作未知病原体（不可信程序），舱内提供完整的实验条件（虚拟资源），但所有空气和废弃物都经过过滤处理（权限拦截与重定向），即使病原体泄漏也只会被锁死在舱内，不会污染外部环境和人员（宿主系统）。

## 2. 形式化描述

### 核心模型

设宿主系统为 $H = (R, P, A)$，其中：

- $R$ 为系统资源集合（文件、内存、网络、设备等）
- $P$ 为进程集合
- $A$ 为访问控制策略

沙箱机制可形式化为一个映射 $S: P_{untrusted} ightarrow (R', P', A')$，满足：

- $R' \subseteq R_{virtual}$（沙箱内进程仅见虚拟/受限资源）
- $P' \cap P_{host} = \emptyset$（进程空间隔离）
- $A' \subseteq A_{whitelist}$（默认拒绝，最小权限原则）
- $orall p \in P_{untrusted}, orall op \in \Sigma_{dangerous}: A'(op) \in \{deny, redirect, emulate\}$

其中 $\Sigma_{dangerous}$ 表示高危系统调用集合（如 `execve`, `ptrace`, `mount`, 原始网络包发送等）。

### 隔离强度谱系

| 隔离层级 | 技术代表 | 隔离对象 | 内核共享 | 启动开销 | 安全强度 |
| --- | --- | --- | --- | --- | --- |
| 硬件级 | 虚拟机 (VM) | 完整操作系统 | 否（独立内核） | 高（分钟级） | 最强 |
| 系统级 | 容器 (Container) | 应用及其依赖 | 是（共享内核） | 低（秒级） | 中等 |
| 进程级 | 沙箱 (Sandbox) | 单个进程/代码片段 | 是（共享内核） | 极低（毫秒级） | 强（聚焦权限） |

> **关键区别**：虚拟机侧重"硬件隔离与多系统部署"，容器侧重"操作系统隔离与应用部署"，沙箱侧重"进程权限限制与安全分析"。三者常组合使用：VM 做底层隔离，容器做应用部署，沙箱做代码安全执行。

## 3. 知识网络

### 上位概念（更抽象）

- [[访问控制 (Access Control)]] — 沙箱是访问控制的一种极端形式：默认拒绝一切，仅显式放行最小必要权限。
- [[虚拟化 (Virtualization)]] — 沙箱利用虚拟化技术构建隔离环境，但虚拟化本身不必然包含安全策略约束。
- [[最小权限原则 (Principle of Least Privilege)]] — 沙箱设计的哲学基础。

### 下位概念（更具体）

- [[系统级沙箱]] — 虚拟化完整计算机软件架构，内部有完整虚拟设备和操作系统（如基于 VM 的恶意软件分析环境）。
- [[容器级沙箱]] — 部署在应用周围的轻量容器，仅隔离必要文件和依赖（如 Docker + Seccomp 的组合）。
- [[浏览器沙箱]] — 将 JavaScript、渲染进程限制在受限空间（如 Chrome 的多层沙箱：Namespace + Seccomp-BPF）。
- [[支付沙箱]] — 模拟真实支付接口，用于测试支付流程而不产生真实资金流动。
- [[云沙箱 vs 硬件沙箱]] — 部署方式差异：云沙箱不受地理限制、成本更低；硬件沙箱满足数据不出局要求。

### 相关/平行概念

| 概念 | 区别 | 联系 |
| --- | --- | --- |
| **虚拟机 (VM)** | 硬件级虚拟化，模拟完整硬件，有独立内核，资源占用高、启动慢 | 系统级沙箱可视为一种特殊 VM，但沙箱更侧重"内部不影响外部"而非"外部不影响内部" |
| **容器 (Container)** | OS 级虚拟化，共用宿主机内核，通过 Namespace/Cgroup 隔离，侧重应用部署 | 容器经加固（如 gVisor, Kata Containers）后可成为沙箱；沙箱可基于容器技术构建 |
| **Honeypot（蜜罐）** | 故意暴露诱饵以吸引攻击者，用于威胁情报收集 | 两者都提供隔离环境，但蜜罐目的是"诱捕"，沙箱目的是"限制与分析" |
| **防火墙 / IDS** | 基于规则的网络流量过滤或入侵检测 | 沙箱提供动态行为分析能力，可弥补静态特征检测的不足，常与防火墙联动 |

## 4. 核心技术实现

### 4.1 资源隔离技术

| 技术 | 作用域 | 原理简述 |
| --- | --- | --- |
| **chroot** | 文件系统 | 改变进程根目录，限制文件系统视图 |
| **Linux Namespace** | PID, NET, IPC, MNT, USER 等 | 隔离进程 ID、网络、挂载点、用户 ID 等全局资源 |
| **Cgroup** | 资源配额 | 限制 CPU、内存、磁盘 I/O、网络带宽使用量 |
| **User Namespace** | 用户权限 | 将沙箱内 root 映射到宿主机普通用户，降低特权逃逸风险 |

### 4.2 权限控制技术

| 技术 | 机制 | 典型应用 |
| --- | --- | --- |
| **Seccomp / Seccomp-BPF** | 系统调用过滤，基于 BPF 规则实现白名单策略 | Chrome、Firefox、Docker 默认启用 |
| **SELinux / AppArmor** | 强制访问控制（MAC），基于安全策略标签限制资源访问 | 企业 Linux 服务器、Android |
| **Capability** | 细粒度 POSIX 权限，剥离进程不必要的特权 | 容器安全加固 |
| **Landlock** | 非特权文件系统访问控制，通过路径层级限制文件操作 | Cursor 等现代开发工具沙箱 |

### 4.3 防躲避技术（Anti-Evasion）

恶意软件常通过检测沙箱特征（如虚拟机注册表键、特殊服务进程、固定硬件序列号、调试器符号链接）来判断自身是否处于分析环境，进而休眠或改变行为。沙箱需具备：

- **环境伪装**：隐藏虚拟机特有的注册表项、服务、驱动；返回合理的硬件指纹与系统序列号。
- **行为诱导**：模拟真实用户交互（鼠标移动、点击、输入），诱导恶意代码触发 payload。
- **时间扭曲**：加速或篡改系统时间，对抗时间延迟型逃逸。
- **深度监控**：监控全部 API 调用、内存分配、网络通信，而非仅依赖签名匹配。

## 5. 典型应用场景

| 场景 | 说明 |
| --- | --- |
| **恶意软件动态分析** | 在隔离环境中执行可疑样本，记录其行为（文件操作、注册表修改、网络通信、进程注入），生成威胁情报 |
| **零日漏洞 / APT 防御** | 弥补传统特征检测的滞后性，通过行为分析识别未知威胁 |
| **浏览器安全** | 隔离网页渲染进程与 JavaScript 执行环境，防止恶意网页访问本地文件系统 |
| **支付与金融测试** | 对接微信/支付宝/银行接口时，使用沙箱环境模拟交易流程，不扣真钱、不写真实账 |
| **DevOps / CI-CD** | 在隔离环境中运行不可信构建脚本或第三方依赖，防止供应链攻击污染构建环境 |
| **AI / 大模型训练** | 隔离调试中的代码，避免影响线上服务；限制模型对系统资源的非授权访问 |

## 6. 关键辨析

- **问：沙箱与容器有何本质区别？**  
答：容器默认侧重"部署隔离"（外部变化不影响内部应用），沙箱侧重"安全隔离"（内部操作不影响外部系统）。容器共享宿主机内核，若未加固（如未启用 Seccomp、未 drop capabilities），其隔离强度不足以对抗恶意代码；沙箱则默认假设程序不可信，采用最小权限与多重边界策略。
- **问：为什么沙箱比虚拟机轻量？**  
答：沙箱通常不虚拟化完整硬件，而是利用操作系统现有机制（Namespace、Seccomp、重定向）对单个进程施加约束，无需启动完整 Guest OS，因此资源占用极低、启动速度极快。
- **问：沙箱能否 100% 防止逃逸？**  
答：不能。沙箱逃逸（Sandbox Escape）是高级威胁研究的活跃领域，内核漏洞、侧信道攻击、配置错误均可能导致逃逸。因此生产环境中常采用**多层嵌套**策略：沙箱内运行不可信代码，沙箱本身运行在容器或虚拟机中，形成纵深防御。
